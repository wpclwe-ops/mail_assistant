# Gmail в Mail Assistant — тестовая версия 3.7.0

## Запуск

1. В GitHub Desktop нажми **Fetch origin**.
2. В **Current branch** выбери **test/gmail**.
3. Закрой старое окно приложения и запусти **START.bat**. Он установит зависимости.
4. На стартовом экране **«Выберите свою почту»** выбери **Gmail**. Для iCloud выбери iCloud — появится прежняя инструкция с паролем приложения Apple.

Приложение должно работать на том же Windows-компьютере, где открывается браузер. Вход Google использует локальный обратный адрес 127.0.0.1 и случайный свободный порт; это не вариант для удалённого сервера.

## Один раз: настройка собственного проекта Google

Пока у приложения нет общего опубликованного OAuth-клиента: для личного тестирования нужен твой проект. Это не создание новой почты и не перенос писем.

1. Открой [Google Cloud Console](https://console.cloud.google.com/), войди в Google.
2. Через меню проектов сверху выбери **New project / Новый проект**. Назови **Mail Assistant** и создай. Убедись, что он выбран.
3. Открой **APIs & Services → Library**, найди **Gmail API**, нажми **Enable / Включить**.
4. Открой **Google Auth platform → Branding → Get started**. Имя приложения — **Mail Assistant**. Email поддержки и контактный email — твой. Для личной почты выбери аудиторию **External**. Закончи настройку.
5. В **Audience** оставь статус **Testing**. В **Test users → Add users** добавь точный адрес Gmail, который будешь подключать.
6. В **Data Access → Add or remove scopes** добавь `https://www.googleapis.com/auth/gmail.modify` и сохрани. Если есть поле ручного добавления, вставь ссылку туда.
7. В **Clients → Create client** выбери тип **Desktop app**. Название — **Mail Assistant Windows**. Нажми **Create**, затем скачай JSON. Не выбирай **Web application**, не создавай API key или service account.
8. Вернись в приложение и загрузи скачанный JSON в **«JSON OAuth-клиента Google»**. Можно также переименовать его в **gmail_credentials.json** и положить рядом с **START.bat** — тогда при следующем запуске приложение найдёт его само. Эти файлы исключены из Git; не публикуй их вручную.

[Официальная инструкция Google](https://developers.google.com/workspace/gmail/api/quickstart/python)

## Каждый вход

1. Выбери **Gmail**, при необходимости загрузи JSON.
2. Нажми **«Войти через Google»**, затем **«Открыть вход Google»**.
3. В новой вкладке выбери Gmail, добавленный в **Test users**, и разреши доступ к почте.
4. Для собственного непроверенного проекта Google может показать предупреждение. Продолжай только если имя проекта соответствует созданному тобой Mail Assistant. Не отключай защиту аккаунта. При блокировке вернись к настройке проекта.
5. После ответа Google вернись в Mail Assistant. Он откроет почту автоматически; пароль Google в приложении не вводится.
6. Нажми **«Обновить почту»**. Первый скан собирает заголовки всех Входящих, поэтому большой ящик может загружаться несколько минут. Прогресс показывается на экране.

Вход ожидает до трёх минут. Если не успела — нажми вход заново. Есть кнопка **«Отменить вход Gmail»**. Не копируй коды и адрес обратного перехода вручную.

## Что можно проверить

- Просмотр отдельных писем и группировка по компаниям.
- Все / Непрочитанные / Прочитанные; поиск и выбор на разных страницах.
- Чтение текста без пометки прочитанным и без загрузки картинок.
- Удаление выбранного письма в Корзину, затем **«Вернуть последнее удаление»**.
- Удаление компании, отписка или оба действия после подтверждения. Автоматическая отписка доступна только при поддержке List-Unsubscribe One-Click; иначе приложение покажет ручную ссылку.
- Белый/чёрный список, история, настройки языка и размера текста.

Пока доступны **Входящие**, а не Архив, Отправленные и остальные папки. Работа идёт с отдельными письмами, а не целыми цепочками. Отправки и окончательного удаления нет.

## Разрешения и сохранение входа

Google не предоставляет узкого разрешения «читать и только переносить в Корзину»: используемый **gmail.modify** также технически допускает создание и отправку писем. Приложение не реализует и не вызывает отправку. Этот scope не разрешает немедленное окончательное удаление в обход Корзины.

Access- и refresh-токены остаются только в памяти процесса. Обновление страницы сохраняет вход через случайную cookie; **«Выйти»**, перезапуск START.bat или завершение приложения потребуют нового входа. Нет файла token.json. Локальная база хранит заголовки, правила, ссылки отписки и историю отдельно для Gmail и iCloud; текст письма не записывается в неё.

Для External-приложений в Testing Google обычно ограничивает refresh-токены семью днями при почтовых scopes. Истёкший или отозванный доступ требует нового входа. Это личная тестовая интеграция; публикация для других пользователей — отдельная задача.

[Разрешения Gmail API](https://developers.google.com/workspace/gmail/api/auth/scopes)
[Правила OAuth и срок refresh-токенов](https://developers.google.com/identity/protocols/oauth2)

## Если не входит

| Сообщение | Что проверить |
|---|---|
| access_denied / только для тестовых пользователей | В Audience → Test users добавлен именно выбранный Gmail |
| redirect_uri_mismatch | JSON создан для Desktop app, не Web application |
| Gmail API disabled / accessNotConfigured | Gmail API включён в том же проекте, где создан OAuth-клиент |
| Нужен JSON Desktop app | Загружен файл клиента с полем installed, не token.json / service account / API key |
| Время входа истекло | Начни вход заново; Google и приложение открыты на одном компьютере |
| Нет ответа Gmail | Интернет доступен; при прерванном удалении проверь Корзину и историю перед повтором |
| Лимит Google | Подожди; прогресс скана не означает зависание |
